# Homebuddy

One application lives in `furniture-catalog/` (the historical directory name). Run `npm run dev` from this repository root.

- `/`: marketing site for uploading floor plans, arranging IKEA furniture, and managing plans with Stripe.
- `/homes`: signed-in list of homes. Upload floor plans and photos. The plan limits how many homes an account can keep. Walkable samples can still open the 3D editor.
- `/account`: name, credits, plan, and Stripe billing.
- Sign-in uses Convex Auth (email and password). Credits are spent on AI arrangements (12) and custom furniture uploads (25).
- `/decorate?home=13`: explore and decorate Spera Plan E (503 sq ft).
- `/decorate?home=15`: explore 333 Bush Street #4101 (1,250 sq ft), with Gather and Retreat furniture arrangements, listing finishes, full appliances, and 11 working doors. Download the furnished Blender scenes through Photos & floor plan.
- `/decorate?home=<id>` accepts either a signed-in home's Convex id (a generated interior) or one of the bundled sample slugs (`13`, `15`, `flowhouse-wb1`). Anything else shows "Home not found". The old San Francisco map and its listing data are gone.
- `/decorate?home=flowhouse-wb1`: Flow House WB1, reconstructed from page 1 of the supplied PDF (970 sq ft plus balcony), with Palm & oak and Quiet mornings furnishing arrangements and Blender downloads. Dimensions and finishes are estimates; details are in `furniture-catalog/app/decorate/homes/flowhouse-wb1/README.md`.
- `/catalog`: the shared furniture library.
- The homepage hero is a self-contained demo of 333 Bush Street: bundled plan data plus the public catalog models it actually places, no Convex subscription, no editor chrome, and it does not mount until scrolled into view. **Full editor** opens the same home in `/decorate`.
- Generating your own home happens on `/homes/<id>`: upload a floor plan (and photos), then **Build the 3D interior**. That records a job in Convex; the generation worker puts the files in an OpenAI sandbox and asks `gpt-6-astra` for the floor plan and any recognizable furniture. When it finishes, the home becomes walkable and any generated models appear in `/catalog`.
- `/furnish?home=15`: the Bush Street demo. Choose catalog furniture or start with Skyline Social / Evening Retreat, review quantities and the catalog subtotal, then ask GPT-6 Astra to arrange the selected pieces. The map opens this flow for Bush Street.

The furnishing demo uses a server-side `OPENAI_API_KEY` with access to `gpt-6-astra`. Set it in the server environment or an ignored `furniture-catalog/.env.local` file before starting the app. No key is sent to the browser. Hosted environments must configure the same key as a secret. The demo is running locally; existing remote deployments have not been changed.

Requests use the OpenAI Responses API in background mode. The arrangement id is stored on the signed-in home, so refreshing the selection page resumes polling without a browser token. The app checks all returned instances for catalog membership, floor containment, wall/fixture/furniture intersections, entrance clearance, door sweeps, and walking routes to every room. It asks Astra for up to two corrections when needed; it does not substitute a preset layout for a failed request. Pieces that cannot fit are listed explicitly. Generated arrangements use the existing 3D editor and do not offer the preset Blender downloads.

Prices are the saved US catalog references checked September 8, 2026, including the sofa prices in `.firecrawl/sofas-ten.md`. Quantity totals use integer cents. Original Homebuddy TV designs have no retail price and are explicitly excluded from the subtotal; tax, delivery, and separately sold accessories are extra.

Demo checks: `cd furniture-catalog && node scripts/check-astra-demo.mjs`.

Catalog models, listing photos, floor-plan downloads, and studio HDRIs are not shipped inside the web app. `npm run seed` (from `furniture-catalog/`) copies binaries into a gitignored local asset store and, when Convex is running, publishes catalog rows and the three sample interiors. The app serves them from `/api/assets/...`. Production sets `ASSET_STORE=s3` with `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, and `S3_BUCKET` on both the web server and the generation process. User uploads and generated models use `homes/{userId}/...` keys and short-lived signed URLs. New uploads do not use Convex file storage. `node scripts/migrate-storage.mjs` copies any existing Convex blobs once; it is a no-op when there are none.

The former `homebuddy-city` project is now only a compatibility launcher. Existing remote deployments are not changed by this local consolidation.

### Upload generation worker

`npm run dev` starts a private, loopback-only Node process beside Next. Convex owns the queue: the web app's `/api/imports` only validates and records a `generationJobs` row (and nudges the worker at `ASSET_WORKER_URL` if configured); the worker claims queued jobs from Convex on a 4-second poll, so a missed nudge leaves a job queued rather than lost. Each job runs two sandbox passes with `gpt-6-astra`: architecture first (`interior.json`), then furniture (GLBs, previews, `catalog.json`). A failure in one pass does not discard the other; a job fails only when neither produced anything usable, and that failure is written back to Convex. Missing API access or unusable references produce a failed job instead of placeholder assets.

Reference files are the home's uploaded floor plans and photos (PNG, JPG, WebP, PDF; 20 MB each). Jobs run one at a time with at most five queued per account, one active per home, and a 45-minute time limit. Workspaces live in ignored `furniture-catalog/.asset-jobs/`; the `job.json` files there are a diagnostic mirror, not the source of truth. Closing the browser does not stop generation. A worker restart marks interrupted jobs failed in Convex. The worker validates the GLB container and embedded resources, file paths, and preview image signatures before publishing to the asset store under `homes/{userId}/catalog/{jobId}/`. Dimensions inferred from references are labeled as estimates. A valid `interior.json` is stored on the home and the decorate/furnish editor opens it; an invalid one is stored as an error and never replaced with a sample apartment. The same `ASSET_WORKER_TOKEN` must be set on the worker process and in the Convex deployment (`npx convex env set ASSET_WORKER_TOKEN <value>`); `npm run dev` warns when it is missing. Arrangement results are stored on the Convex arrangement, not in this browser.

The web app is Next.js. Deploy `furniture-catalog/` to Vercel and set `NEXT_PUBLIC_CONVEX_URL`, `CONVEX_URL`, `ASSET_STORE=s3`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `S3_BUCKET`, `ASSET_WORKER_URL`, and `ASSET_WORKER_TOKEN`. Catalog and private file URLs redirect to S3, and browser uploads go straight to the bucket, so large models do not pass through the Vercel function. Allow `s3:GetObject` and `s3:PutObject` for the app key, and add a bucket CORS rule that allows `GET` and `PUT` from the Vercel origin and `http://localhost:3000`.

Generation cannot run inside a Vercel request. Run `node server/asset-worker.mjs` on a host that can stay up for the sandbox session, with `OPENAI_API_KEY` and the same `ASSET_WORKER_TOKEN` set in the Convex deployment. That process starts the OpenAI sandbox, waits, and stores the files. It does not use the Codex CLI. Server-side API routes share one Convex bootstrap in `furniture-catalog/lib/server/convex.ts`. It defaults to `127.0.0.1:4319`; use `PORT`, `ASSET_WORKER_HOST`, and `ASSET_WORKER_DATA_DIR` for its listener and scratch volume. Expose it only behind authenticated HTTPS. Do not put the worker token or AWS credentials in browser code. Without that process, uploads show an explicit unavailable state.

Run `cd furniture-catalog && node scripts/check-asset-imports.mjs` for isolated integration checks of worker authorization, input ownership, idempotent job adoption, two-pass generation, partial results, failure reporting, restart handling, and the enqueue-only web route. These checks use an injected generator and a temporary asset store and do not spend model credits.

The apartment editor includes Morning, Daylight, Golden hour, and Night lighting. Auto follows San Francisco time (morning 6–10, daylight 10–17, golden hour 17–20, night 20–6); these are preview periods, not a solar simulation. The selected mode is remembered on this browser.

In Walk mode, ambient light and reflections follow connected space from windows and declared fixtures. Walls and closed doors block this indirect fill; unlit closets receive spill only through an open doorway. Direct lights retain their shadow maps. The roofless overview keeps its presentation lighting.

Bush Street also offers three ready-to-view suggestions: Skyline Social, Evening Retreat, and City living. The first two are saved presets; City living is a checked result from a real GPT-6 Astra request, stored as placement data in `app/furnish/saved-astra-layout.json`. Opening and switching these suggestions never starts an OpenAI generation. A new successful Astra arrangement appears alongside all three in the same editor, and the displayed subtotal follows the selected arrangement.

The request status appears above the catalog and comes into view on start or completion. It distinguishes submitting, OpenAI-confirmed activity (with elapsed time and last confirmation), refinement, reconnection, success, failure, cancellation, and an unconfirmed submission. Saved layouts remain available during generation. A real browser-started Astra request completed with all 24 selected pieces placed after layout refinement, and the result rendered in the 3D editor. Browser checks cover map entry, totals, request resumption after refresh, saved-layout switching, generated/preset switching, and walking mode; failure/cancellation/reconnection are exercised with an isolated local response fixture.
